# 퇴근 알림 (2026-11-10 초안 → 2026-11-20 확정·구현)

> **상태: 구현됨.** 화면·문구 확정본은 `design-handoff-6-partial-trip-notification.md` §7~§10, 구현 확정 규칙은 이 문서 §8.
> §1~§7은 논의 기록이다 — §8과 다르면 §8이 맞다. 기기에서 확인할 것은 `2026-11-20-notification-device-checklist.md`.

## 0. 왜

- 요청: "퇴근할 때 되면 알림 보내기 → 워치에도 오게끔. 정시 / 10분 전 / 5분 전 고를 수 있게?"
- **1차는 정시만.** 10분 전·5분 전·30분 전 등 예고 알림은 뺀다 — 설정·문구·Android 정확한 알람 권한이 전부 단순해진다.
  요청자에게 "1차는 정시만, 써보고 필요하면 추가"로 전달. 나중에 추가할 수 있게 예약 로직은 "알림 목록을 받아 예약"하는 형태로 둔다.
- 알림 액션("퇴근하기" 버튼)은 **만들지 않는다.** 출퇴근은 오늘 화면이 찍는다.

## 1. 알림 두 종류

| 이름 | 언제 | 예고 옵션 |
|---|---|---|
| **일일 알림** | 그날 기준시간을 채우는 시각 (T기준) | 없음 (정시만) |
| **주간 알림** | 이번 주 목표를 채우는 시각 (T주간), 오늘 안일 때만 | 없음 |

- **T기준** = 출근 시각 + 그날 기준시간(일반 8h · 반차 4h − 시간공제), 점심 창에 걸리면 창 뒤로 밀림.
  `expectedClockOut`과 같은 계산에 오늘 몫 대신 그날 기준시간을 넣는다. 예: 8:30 출근 → 17:30. 반차 8:30 → 12:30.
- **T주간** = 출근 시각 + 이번 주 남은 시간(목표 − 오늘 이전 평일 실근무), 같은 점심 처리.
- 주간 잔여 기준 "오늘 몫"(균등 배분)은 쓰지 않는다 — 알림 시각이 매일 달라져 헷갈린다.

## 2. 규칙

| 경우 | 알림 |
|---|---|
| 출근 전에 이미 주간 목표를 채움 | 없음 |
| 마지막 근무일, 또는 T주간 ≤ T기준 | T주간에 주간 알림 하나. 일일 알림은 건너뜀 |
| 그 외 | T기준에 일일 알림만 |
| 첫 주 예외 | 일일 알림만 (주간은 판단 불가) |
| 주말·공휴일 근무 | 없음 (그날 기준이 없다) |
| 쉬는 날 | 없음 (출근이 없다) |

- **알림 하나 = "이제 가도 돼요".** 마지막 근무일은 주간이 모자라도 T기준에 부족 알림을 보내지 않고 T주간에 한 번만 보낸다
  (2026-11-20). 예: 금요일 남은 시간 6h → 6h에 한 번 · 8h → 8h에 한 번 · 10h → 10h에 한 번.
  "아직 남았어요" 알림은 같은 진동에 반대 뜻이 섞이고(워치에선 문구를 안 읽는다), 알림이 안 온 것 자체가 "아직"이라는 뜻이라 뺐다.
- 마지막 근무일 판정은 안내 문구와 같은 기준(실제 근무일, 연차·공휴일·출장 제외).

## 3. 문구 케이스 (케이스 확정 2026-11-20, 문구는 디자인에서)

케이스 분류는 여기서 정하고 문구는 Claude Design에 맡긴다. 아래 "예시"는 임시다.

**알림 (제목 + 본문)**

| # | 경우 | 예시 (임시) |
|---|---|---|
| N1 | 일일 알림 — 그날 기준시간을 채움. 반차·시간공제·시간 출장·첫 주 예외 날도 같은 문구 | "퇴근할 시간이에요!" |
| N2 | 주간 알림 — 이번 주 목표를 채움 (마지막 근무일, 또는 주간이 먼저 끝난 날) | "이번 주 다 채웠어요" |
| N3 | 예약 시각이 이미 지나서 즉시 보내는 경우 — N1·N2와 같은 문구로 갈지 따로 둘지도 디자인에서 | "퇴근 시간이 지났어요" |

**권한·설정**

| # | 위치 | 필요한 문구 |
|---|---|---|
| P1 | 첫 출근 때 묻는 화면 | 제목 · 설명 · 수락 · 거절 (예: "퇴근 시간에 알려드릴까요?") |
| P2 | 거절 직후 토스트 | 예: "설정에서 언제든 켤 수 있어요" |
| P3 | 설정 "알림" 섹션·행 | 섹션 제목 · 행 제목 · 보조 설명(켜짐/꺼짐) |
| P4 | OS 권한이 꺼진 상태에서 켜려 할 때 | OS 설정 안내 문구 + 버튼 |

알림이 없는 경우(문구 불필요): 주말·공휴일 근무, 쉬는 날, 출근 전에 이미 주간 목표를 채운 주, 기준 전에 퇴근한 날(공제하고 퇴근 포함).

문구는 `<feature>_texts.dart`에서만 조립한다.

## 4. 예약·취소

서버가 없으므로 **OS 로컬 예약 알림**(앱이 꺼져 있어도 울림). 오늘 상태가 바뀌면 한 곳에서 예약을 다시 맞춘다
(버튼마다 따로 처리하지 않는다 — 빠지는 경우가 생긴다).

| 사건 | 처리 |
|---|---|
| 출근 | 예약 |
| 퇴근 (일찍 퇴근 포함) | 오늘 알림 전부 취소 — 기준 전에 퇴근하면 일일 알림 안 감 |
| 출근 취소 | 전부 취소 |
| 출근 변경 | 다시 예약 |
| 오늘 반차 체크/해제 | 다시 예약 (4h ↔ 8h) |
| 근무 중 지난 날 기록 수정 | 다시 예약 (주간 잔여가 바뀜) |
| 알림 끔 | 전부 취소 |

- 예약 시각이 이미 지났으면(출근 변경 등) **즉시 보낸다** (2026-11-20, 문구 N3).
- 디버그 시계(`DebugClockOffset`)와 OS 예약 시각이 어긋난다 — 디버그에서 오프셋을 빼고 예약하거나 즉시 발송 버튼 (§7).
- "남은 시간 공제하고 퇴근"은 별도 처리 없음 — 그 버튼으로 퇴근하는 순간 "퇴근 = 전부 취소"로 남은 알림이 사라진다 (2026-11-20).

## 5. 권한·설정

- **첫 "출근하기"를 누를 때 한 번** 묻는다. 신규 사용자와 기존 사용자(업데이트 후 첫 출근)가 같은 규칙.
  수락 → OS 권한 요청 → 켜짐. 거절·넘김 → 다시 묻지 않고 토스트로 "설정에서 켤 수 있다"를 알린다 (P2, 2026-11-20).
- 설치 직후에는 묻지 않는다 — iOS는 한 번 거절하면 다시 물을 수 없고, 온보딩이 없어 맥락 없이 물으면 거절되기 쉽다.
- 설정 화면에 **"알림" 섹션, 켜기/끄기 하나.** `Settings` 테이블 키 추가(스키마 변경 없음). 물어봤는지 여부도 키로.
- 백업 포함 여부 — §7.

## 6. 플랫폼

- **워치**: 별도 앱 없음. iPhone 알림은 Apple Watch로, Android 알림은 Wear OS·갤럭시 워치로 OS가 미러링한다.
- **iOS**: 알림 권한.
- **Android**: Android 13+ `POST_NOTIFICATIONS`. 정시만 보내므로 **정확한 알람 권한(`SCHEDULE_EXACT_ALARM`) 없이** 일반 예약으로 갈 수 있는지 검토
  (1~2분 지연은 허용). 재부팅 후 예약 복원(`RECEIVE_BOOT_COMPLETED`), 제조사 배터리 최적화.
- 패키지 후보: `flutter_local_notifications` + `timezone`(+ 기기 시간대). CLAUDE.md 플랫폼 패키지 목록에 추가.
- 구조: `BackupFiles`처럼 domain 포트(알림 예약) + data 구현. 테스트는 Fake로 "무엇이 언제 예약됐는지" 검증.

## 8. 구현 확정 규칙 (2026-11-20)

### 무엇을 언제 — `planClockOutNotice` (`lib/domain/notification/clock_out_notice.dart`)

```
근무 중(출근 있음 · 퇴근 없음)이 아니면            → 없음
주말 · 공휴일 근무                                → 없음
T기준 = 출근 + 그날 기준시간 (점심 창에 걸리면 창 뒤로)
첫 주 예외                                        → 일일(N1) @ T기준
출근 전에 이미 이번 주를 채움                      → 없음
T주간 = 출근 + 이번 주 남은 시간
마지막 근무일                                     → 주간(N2) @ T주간
T주간 ≤ T기준                                     → 주간(N2′) @ T주간
그 외                                             → 일일(N1) @ T기준
```

- 그날 기준시간이 0(공제로 다 빠진 날)이면 일일 알림은 없다.
- **알림 시각이 오늘을 넘기면(자정 뒤) 없다** — 일일·주간 모두. 16:30 출근 일반 근무일은 다음 날 00:30이라 없다.
- 시간 출장 범위는 보지 않는다. 오늘 몫(균등 배분)도 쓰지 않는다.

### 예약 맞추기 — `ClockOutNotificationSync` (`lib/presentation/notification/`)

**OS 예약을 건드리는 곳은 여기 하나다.** 버튼마다 따로 예약하지 않는다.

```
알림 꺼짐 · OS 권한 없음 · 정시 권한 없음(Android) · 계획 없음   → 예약 취소 (오늘 전달된 기록은 남긴다)
계획 시각이 아직 안 옴                 → 같은 알림이 이미 예약돼 있으면 그대로, 아니면 예약(대체) + 저장
계획 시각이 이미 지남 (N3)             → 오늘 이미 전달됐으면 아무것도 안 함, 아니면 지금 띄우고 저장
```

- 다시 맞추는 사건: 기록·첫 기록일 스트림 · 날짜 바뀜 · 알림 설정 · 디버그 시계 이동 · **앱으로 돌아옴**(이때 매 분 시계도 새로 흘린다).
- **저장된 알림**(Settings 키 `clock_out_notice`): 마지막으로 예약했거나 바로 띄운 알림. 시각이 지났으면 OS가 이미 띄운 것으로 본다.
  그래서 퇴근 시각 뒤에 앱을 다시 켜거나 · 지난 기록을 고치거나 · 알림을 껐다 켜거나 · 퇴근을 취소해도 **같은 날 다시 울리지 않는다.**
  계획이 미래로 옮겨가면(반차 해제, 출근을 늦춤) 새 시각에는 다시 예약한다 — 앞의 알림이 틀린 데이터로 울린 것이다.
- 계획은 맞추는 순간의 시각으로 다시 센다. 프로바이더의 "오늘"은 매 분 시계에서 오는데 앱이 밤새 멈춰 있다 돌아오면 어제에 머물 수 있다.
- 앱을 막 켰을 땐 저장된 값만 믿지 않고 한 번은 다시 건다(강제 종료 등으로 OS 예약이 사라졌을 수 있다).
- 실패하면 20초 뒤 스스로 다시 시도한다(연달아 3번까지). 알림 오류는 출퇴근 기록을 막지 않는다.
- OS에 넘기는 시각 = 계획 시각 − 디버그 시계 오프셋(릴리즈는 0), UTC 절대 시각, 초 아래 버림.

### 권한·설정

- **P1은 첫 평일 출근 직후 한 번.** 주말·공휴일 근무 출근은 건너뛰고 다음 평일 출근 때 묻는다. 수락·거절·바깥 탭 모두 "물어봤다"(`notification_prompted`).
- OS 권한 상태: OS가 허용이면 `granted`. 아니고 우리가 OS 창을 띄운 적이 없으면(`notification_os_asked` 없음) `notDetermined`, 있으면 `denied`.
  OS는 "아직 안 물어봄"과 "거부함"을 구분해 주지 않는다.
- 설정 행: `denied`면 켜짐 여부와 무관하게 "설정 열기" 행(P4). 그 외는 토글(값 = `clock_out_notification`).
  켰는데 OS 창에서 거절하면 켜짐은 남는다 — OS에서 허용하고 돌아오면 바로 예약된다.
- Settings 키 넷: `clock_out_notification`(켜져 있으면 `on`) · `notification_prompted` · `notification_os_asked` · `clock_out_notice`. **넷 다 백업에 넣지 않는다**(기기 값).

- Android: `POST_NOTIFICATIONS` · `RECEIVE_BOOT_COMPLETED` · 리시버 둘(예약 표시 · 재부팅 뒤 복원) · core library desugaring ·

  처음엔 권한 없이 가기로 했으나(§6·§7-4) 실기기 측정으로 뒤집었다 (2026-11-20, Galaxy A16 · Android 16):

  | 예약 | OS가 잡은 허용 오차 | 실제 |
  |---|---|---|
  | 권한 없음, 5분 뒤 | 3분 44초 | 3분 45초 늦게(오차의 끝에서) |
  | 권한 없음, 약 2시간 뒤 | **1시간** | — |
  | 권한 있음, 약 2시간 뒤 | 0 | — |

  **늦게 오는 알림은 보내지 않기로 했다(사용자 결정): 정시에 못 보내면 아예 안 보낸다.**

- "알람 및 리마인더" 화면 (핸드오프 6 §10 P6~P8, 2026-11-20 디자인 확정): 알림을 켠 직후 권한이 없으면 다이얼로그(P6)
  "하나만 더 허용해 주세요 / 기기 설정에서 '알람 및 리마인더'를 허용해야 퇴근 시각에 맞춰 알림이 와요. / 나중에 · 설정 열기".
  넘기거나 허용하지 않고 돌아오면 토스트(P7) "설정에서 언제든 허용할 수 있어요", 허용하고 돌아오면 아무것도 띄우지 않는다.
  안 켠 동안 설정 알림 섹션의 토글 아래에 "알람 및 리마인더 · 허용해야 퇴근 알림이 와요 · 설정 열기" 행(P8) — 누르면 다이얼로그 없이
  시스템 화면으로 바로 간다(행 이름 = 스위치 이름). 켜고 돌아오면 행이 사라지고 그때 예약이 걸린다. 토글은 "받고 싶다"는 뜻이라 켜짐 그대로 둔다.
  창이 P1 → OS 알림 → P6 세 번 이어지는 흐름은 줄이지 않는다(디자인 결정).
- iOS: `AppDelegate`에서 `UNUserNotificationCenter.current().delegate` 설정 — 없으면 앱을 보고 있을 때 배너가 안 뜬다.
  초기화에서 권한을 묻지 않는다.
- 워치: 별도 앱 없음. OS가 넘긴다. 넘어가는 걸 막는 옵션을 쓰지 않고 소리·진동이 있는 중요도(`Importance.high`)로 보낸다.

### §7 열린 질문 결과

1. 문구 — 핸드오프 6 §10으로 확정.
2. 이미 지난 시각 — 즉시 발송, 단 하루 한 번.
3. "공제하고 퇴근" — 퇴근 = 전부 취소로 해결.
4. Android 지연 — 측정 결과 권한 없이는 최대 1시간. "알람 및 리마인더" 권한이 있을 때만 정시로 걸고, 없으면 보내지 않는다(위 플랫폼 절).
5. 백업 — 넣지 않는다.
6. 디버그 시계 — 오프셋을 빼고 예약 + 디버그 시트의 시험 버튼 둘.
7. 예고 알림 — 실사용 뒤.
