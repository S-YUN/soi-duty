# 퇴근 알림 (초안, 2026-11-10)

> **상태: 초안.** 논의 내용 정리만 한 것. 구현 전 열린 질문(§7)을 확정한다.
> **알림 문구는 전부 임시다 — 확정 아님.**

## 0. 왜

- 요청: "퇴근할 때 되면 알림 보내기 → 워치에도 오게끔. 정시 / 10분 전 / 5분 전 고를 수 있게?"
- **1차는 정시만.** 10분 전·5분 전·30분 전 등 예고 알림은 뺀다 — 설정·문구·Android 정확한 알람 권한이 전부 단순해진다.
  요청자에게 "1차는 정시만, 써보고 필요하면 추가"로 전달. 나중에 추가할 수 있게 예약 로직은 "알림 목록을 받아 예약"하는 형태로 둔다.
- 알림 액션("퇴근하기" 버튼)은 **만들지 않는다.** 출퇴근은 오늘 화면이 찍는다.

## 1. 알림 두 종류

| 이름 | 언제 | 예고 옵션 |
|---|---|---|
| **일일 알림** | 그날 기준시간을 채우는 시각 (T기준) | 없음 (정시만) |
| **주간 알림** | 이번 주 목표를 채우는 시각 (T주간), 오늘 안일 때만 | 없음 |

- **T기준** = 출근 시각 + 그날 기준시간(일반 8h · 반차 4h − 시간공제), 점심 창에 걸리면 창 뒤로 밀림.
  `expectedClockOut`과 같은 계산에 오늘 몫 대신 그날 기준시간을 넣는다. 예: 8:30 출근 → 17:30. 반차 8:30 → 12:30.
- **T주간** = 출근 시각 + 이번 주 남은 시간(목표 − 오늘 이전 평일 실근무), 같은 점심 처리.
- 주간 잔여 기준 "오늘 몫"(균등 배분)은 쓰지 않는다 — 알림 시각이 매일 달라져 헷갈린다.

## 2. 규칙

| 경우 | 알림 |
|---|---|
| 출근 전에 이미 주간 목표를 채움 | 없음 |
| 마지막 근무일, 또는 T주간 ≤ T기준 | T주간에 주간 알림 하나. 일일 알림은 건너뜀 |
| 그 외 | T기준에 일일 알림만 |
| 첫 주 예외 | 일일 알림만 (주간은 판단 불가) |
| 주말·공휴일 근무 | 없음 (그날 기준이 없다) |
| 쉬는 날 | 없음 (출근이 없다) |

- **알림 하나 = "이제 가도 돼요".** 마지막 근무일은 주간이 모자라도 T기준에 부족 알림을 보내지 않고 T주간에 한 번만 보낸다
  (2026-11-20). 예: 금요일 남은 시간 6h → 6h에 한 번 · 8h → 8h에 한 번 · 10h → 10h에 한 번.
  "아직 남았어요" 알림은 같은 진동에 반대 뜻이 섞이고(워치에선 문구를 안 읽는다), 알림이 안 온 것 자체가 "아직"이라는 뜻이라 뺐다.
- 마지막 근무일 판정은 안내 문구와 같은 기준(실제 근무일, 연차·공휴일·출장 제외).

## 3. 문구 케이스 (케이스 확정 2026-11-20, 문구는 디자인에서)

케이스 분류는 여기서 정하고 문구는 Claude Design에 맡긴다. 아래 "예시"는 임시다.

**알림 (제목 + 본문)**

| # | 경우 | 예시 (임시) |
|---|---|---|
| N1 | 일일 알림 — 그날 기준시간을 채움. 반차·시간공제·시간 출장·첫 주 예외 날도 같은 문구 | "퇴근할 시간이에요!" |
| N2 | 주간 알림 — 이번 주 목표를 채움 (마지막 근무일, 또는 주간이 먼저 끝난 날) | "이번 주 다 채웠어요" |
| N3 | 예약 시각이 이미 지나서 즉시 보내는 경우 — N1·N2와 같은 문구로 갈지 따로 둘지도 디자인에서 | "퇴근 시간이 지났어요" |

**권한·설정**

| # | 위치 | 필요한 문구 |
|---|---|---|
| P1 | 첫 출근 때 묻는 화면 | 제목 · 설명 · 수락 · 거절 (예: "퇴근 시간에 알려드릴까요?") |
| P2 | 거절 직후 토스트 | 예: "설정에서 언제든 켤 수 있어요" |
| P3 | 설정 "알림" 섹션·행 | 섹션 제목 · 행 제목 · 보조 설명(켜짐/꺼짐) |
| P4 | OS 권한이 꺼진 상태에서 켜려 할 때 | OS 설정 안내 문구 + 버튼 |

알림이 없는 경우(문구 불필요): 주말·공휴일 근무, 쉬는 날, 출근 전에 이미 주간 목표를 채운 주, 기준 전에 퇴근한 날(공제하고 퇴근 포함).

문구는 `<feature>_texts.dart`에서만 조립한다.

## 4. 예약·취소

서버가 없으므로 **OS 로컬 예약 알림**(앱이 꺼져 있어도 울림). 오늘 상태가 바뀌면 한 곳에서 예약을 다시 맞춘다
(버튼마다 따로 처리하지 않는다 — 빠지는 경우가 생긴다).

| 사건 | 처리 |
|---|---|
| 출근 | 예약 |
| 퇴근 (일찍 퇴근 포함) | 오늘 알림 전부 취소 — 기준 전에 퇴근하면 일일 알림 안 감 |
| 출근 취소 | 전부 취소 |
| 출근 변경 | 다시 예약 |
| 오늘 반차 체크/해제 | 다시 예약 (4h ↔ 8h) |
| 근무 중 지난 날 기록 수정 | 다시 예약 (주간 잔여가 바뀜) |
| 알림 끔 | 전부 취소 |

- 예약 시각이 이미 지났으면(출근 변경 등) **즉시 보낸다** (2026-11-20, 문구 N3).
- 디버그 시계(`DebugClockOffset`)와 OS 예약 시각이 어긋난다 — 디버그에서 오프셋을 빼고 예약하거나 즉시 발송 버튼 (§7).
- "남은 시간 공제하고 퇴근"은 별도 처리 없음 — 그 버튼으로 퇴근하는 순간 "퇴근 = 전부 취소"로 남은 알림이 사라진다 (2026-11-20).

## 5. 권한·설정

- **첫 "출근하기"를 누를 때 한 번** 묻는다. 신규 사용자와 기존 사용자(업데이트 후 첫 출근)가 같은 규칙.
  수락 → OS 권한 요청 → 켜짐. 거절·넘김 → 다시 묻지 않고 토스트로 "설정에서 켤 수 있다"를 알린다 (P2, 2026-11-20).
- 설치 직후에는 묻지 않는다 — iOS는 한 번 거절하면 다시 물을 수 없고, 온보딩이 없어 맥락 없이 물으면 거절되기 쉽다.
- 설정 화면에 **"알림" 섹션, 켜기/끄기 하나.** `Settings` 테이블 키 추가(스키마 변경 없음). 물어봤는지 여부도 키로.
- 백업 포함 여부 — §7.

## 6. 플랫폼

- **워치**: 별도 앱 없음. iPhone 알림은 Apple Watch로, Android 알림은 Wear OS·갤럭시 워치로 OS가 미러링한다.
- **iOS**: 알림 권한.
- **Android**: Android 13+ `POST_NOTIFICATIONS`. 정시만 보내므로 **정확한 알람 권한(`SCHEDULE_EXACT_ALARM`) 없이** 일반 예약으로 갈 수 있는지 검토
  (1~2분 지연은 허용). 재부팅 후 예약 복원(`RECEIVE_BOOT_COMPLETED`), 제조사 배터리 최적화.
- 패키지 후보: `flutter_local_notifications` + `timezone`(+ 기기 시간대). CLAUDE.md 플랫폼 패키지 목록에 추가.
- 구조: `BackupFiles`처럼 domain 포트(알림 예약) + data 구현. 테스트는 Fake로 "무엇이 언제 예약됐는지" 검증.
