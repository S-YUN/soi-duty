# 점심시간 설정 — 고민 메모 (2026-11-12)

> **상태: 보류.** 만들지 않기로 한 게 아니라, 요청이 오면 다시 보기 위한 메모. 스펙 아님.

## 아이디어

기본은 12:00–13:00 그대로, 설치할 때 묻지 않고 설정에서만 바꾸게 한다.
CLAUDE.md의 기존 방침("점심 시작 시각은 지금 기본값만 쓰고, 테스터가 12시가 아니라고 할 때 설정으로 뺀다")과 같은 방향.
`WorkRules`가 인스턴스라 구조는 준비돼 있다(`lunchStartMinutes`, `lunchBreakMinutes`).

## 어려운 점

점심시간에는 세 가지가 섞여 있다 — **언제 먹느냐 · 얼마나 먹느냐 · 그중 얼마가 근무에서 빠지느냐.** 앱이 알아야 하는 건 마지막 하나다.

1. **길이가 바뀌면 소급 문제.** 파생값을 저장하지 않으므로 설정을 바꾸면 지난 기록도 새 규칙으로 다시 계산된다.
   1h → 1h 30m으로 바꾸면 지난 9–18시 근무가 전부 −30m. 지난 주는 표시만 이상해지지만,
   **이번 주 중간에 바꾸면 앞선 날들이 모자란 걸로 바뀌어 잔여가 갑자기 늘어난다.**
   해결하려면 적용 시작일(오늘부터 / 처음부터)을 저장하고 날짜별로 점심시간을 찾아 써야 한다 — 계산 구조 변경이 크다.
2. **복지형 회사는 바뀐 게 없다.** 점심을 1h 30m 먹어도 근무에서 1h만 빠지면(퇴근 그대로) 앱 설정은 그대로여야 한다.
   설정 이름이 그냥 "점심시간"이면 이 사용자가 1h 30m으로 바꿔서 매일 30분씩 모자라게 나온다 →
   "근무시간에서 빠지는 점심시간"이라는 뜻을 이름·안내로 분명히 해야 한다.
3. 시각만 옮기는 경우(12–13 → 11:30–12:30)는 소급해도 9–18시 같은 평범한 날은 결과가 같다 — 경계에 걸린 날만 달라진다.

## 선택지 (다시 볼 때)

| 안 | 내용 | 비고 |
|---|---|---|
| 1 | 만들지 않음 (지금) | 요청이 올 때까지 기다린다 |
| 2 | **시작 시각만**, 길이 1h 고정 | 소급·복지형 혼동 거의 없음. 실제 요청 대부분일 것. 3으로 넓히기 쉬움 |
| 3 | 시작~끝 (길이 포함) | 가장 유연. "공제되는 시간" 설명 필요, 길이 변경 시 소급 문제 — 1차는 소급 + "지난 기록에도 적용돼요" 안내, 적용 시작일은 요청 오면 |

"점심 1h 30m이 전부 근무에서 빠진다"는 요청이 실제로 오면 그 사람 상황에 맞춰 3을 설계한다.

## 만들게 되면 영향받는 곳

- `workRules` 프로바이더가 설정을 읽게 됨 (계산 함수는 이미 `WorkRules`를 인자로 받음)
- 근무 중 실시간 진행분, 시트 "점심 공제" 줄(최대치 = 길이), 퇴근 알림 시각(변경 시 다시 예약)
- 시간 출장은 범위 통째 인정이라 무관
- `Settings` 키 추가(스키마 변경 없음), 백업 `settings`에 포함 — 시간 출장의 백업 format 3과 함께 올리면 한 번에
- 설정 화면: 기본값 있는 행 → "기본값으로 되돌리기"
