# 퇴근 알림 — 기기 확인표 (2026-11-20)

자동 테스트는 "무엇을 언제 예약·취소하는지"까지만 본다. **OS가 실제로 띄우는지, 워치로 가는지, 얼마나 늦는지**는 기기에서 봐야 한다.
dev 빌드(`--flavor dev`)로 확인한다 — 디버그 시트가 필요하다.

## 빌드 환경

Android·iOS 빌드와 서명은 맥(Flutter 3.47.4)에서 확인했고 1.0.4+6으로 두 스토어에 올렸다 (2026-11-22).

**알림 패키지를 22.3.x로 묶은 이유.** 23.x는 Android에서 AGP 9.1.1 이상 · compileSdk 37 이상을 요구한다.
작업 당시 AGP는 9.1.0(`android/settings.gradle.kts`, 레포에 있어 어느 PC든 같다), compileSdk는 36(설치된 Flutter의 기본값 — **PC의 Flutter 버전에 따라 다르다**)이었다.
쓰는 Flutter가 compileSdk 37을 기본으로 쓰고 AGP를 올려도 되는 상태면 23.x로 올릴 수 있다 — 꼭 올릴 필요는 없다(22.3.3으로 필요한 기능은 다 된다).
올린다면 고칠 곳은 `android/settings.gradle.kts`의 AGP 버전과 `pubspec.yaml` 한 줄이고, Dart 쪽은 `lib/data/notification/local_notification_scheduler.dart`만 보면 된다.

## 준비

- 오늘 화면의 **날짜 제목을 길게 누르면** 디버그 시트가 열린다. 가운데에 알림 시험 버튼 둘:
  - **알림 지금 보내기** — 누르는 순간 띄운다.
  - **1분 뒤 알림 예약** — 예약만 한다. 누른 뒤 앱을 내리거나 · 끄거나 · 화면을 잠그고 기다린다.
  - 둘 다 앱의 알림 설정(켜짐/꺼짐)과 무관하게 OS에 바로 건다. 권한이 없으면 OS 창이 먼저 뜬다.
- 실제 흐름(출근 → 퇴근 시각에 알림)을 빨리 보려면 **출근 변경**으로 출근 시각을 앞당긴다.
  예: 지금 15:00이면 출근을 06:58로 → 일반 근무 기준 15:58에 울린다(점심 1시간 포함 9시간 뒤).
  반차를 체크하면 4시간 뒤라 더 쉽다(출근 10:58 → 14:58).
- 디버그 시계를 옮겨도 알림은 **실제 시각**에 맞춰 울린다(앱 시각 − 옮긴 만큼).

결과는 ✅ / ❌ 와 메모(기종 · OS 버전 · 늦은 시간)로 적는다.

**iOS 실기기 디버그 빌드는 화면을 잠그면 `flutter run` 연결이 끊긴다**(2026-11-21, iPhone 11). 끊긴 디버그 앱은 홈 화면에서 다시 열 수 없다 —
잠금 화면·앱 종료 항목(2-3·2-4·3절)은 **디버그 도구를 켠 릴리즈 빌드**로 본다:
`flutter run --release --flavor dev --dart-define=SOI_DEBUG_TOOLS=true -d <기기>` — 릴리즈인데 날짜 제목 길게 누르기가 된다(`lib/core/debug_tools.dart`).
설치만 되면 케이블·맥 없이 홈 화면에서 다시 열 수 있다. 스토어 빌드(`scripts/release.sh`)에는 이 값이 없어 디버그 도구가 들어가지 않는다.

**에뮬레이터로 돌리는 법 (2026-11-20, Pixel 8 API 34).** adb로 전부 조작할 수 있다. 시계는 `adb shell settings put global auto_time 0` 뒤
`adb shell cmd alarm set-time <epoch ms>`로 옮긴다(루트 불필요) — 출근을 찍고 알림 시각 10초 전으로 옮기면 실제 울림까지 바로 본다.
예약은 `adb shell dumpsys alarm | grep -A2 "Alarm{.*soiduty"`(`window=0`이면 정시), 온 알림은 `dumpsys notification --noredact`의 `when=`.
권한을 밖에서 끄려면 `cmd appops set --uid <pkg> SCHEDULE_EXACT_ALARM deny`(`--uid` 없이는 안 먹는다).
**재부팅 시험 전에는 `cmd appops write-settings`** — 안 하면 방금 켠 "알람 및 리마인더"가 디스크에 안 써진 채 재부팅돼 권한이 풀리고,
부트 리시버가 "Exact alarms are not permitted"로 복원을 포기한다(시험 방식의 문제지 앱 문제가 아니다).
에뮬레이터로 못 보는 것: 제조사 절전(5-4), 워치(3절), 잠금 화면 표시, Android 12~13.

**시험 버튼으로 잠금 화면을 볼 때 (2026-11-21).** 앱은 화면으로 돌아올 때마다 계획과 OS 예약을 맞추는데, 계획이 없는 날(주말)에는 걸린 예약을 전부 치운다 —
시험 버튼이 건 예약도 같이 지워져 iPhone에서 앱을 띄운 채 잠그면 알림이 오지 않았다(앱을 밀어 끄고 잠그면 왔다). 시험 알림이 울릴 때까지 예약 맞추기를 쉬게 고쳤다
(`ClockOutNotificationSync.debugTestUntil`). 실제 알림은 계획이 있어 같은 시각으로 다시 걸리니 해당 없다.

## 알려진 한계 (버그 아님)

- **예약 시각에 폰이 꺼져 있었으면** 켠 뒤에 늦게 뜰 수 있다.
- **Android에서 설정 > 앱 > 강제 종료**를 하면 OS가 예약을 지운다. 앱을 다시 열면 다시 걸린다.
- **알림 시각이 자정을 넘기면 보내지 않는다.** 16:30에 출근한 일반 근무일은 8시간 뒤가 다음 날 00:30이라 알림이 없다.
- **한 번 울린 날은 다시 "바로 띄우기"를 하지 않는다.** 울린 뒤 퇴근 취소·알림 껐다 켜기를 해도 조용하다. 퇴근 시각이 뒤로 밀리면(반차 해제 등) 새 시각에는 온다.
- **Android에서 "알람 및 리마인더"를 안 켜면 알림이 오지 않는다.** 권한 없이 걸면 OS가 최대 1시간 늦추기 때문에, 늦게 보내느니 보내지 않기로 했다. Android 14+는 사용자가 시스템 설정에서 직접 켜야 해서 앱이 안내한다.
