# 퇴근 알림 — 기기 확인표 (2026-11-20)

자동 테스트는 "무엇을 언제 예약·취소하는지"까지만 본다. **OS가 실제로 띄우는지, 워치로 가는지, 얼마나 늦는지**는 기기에서 봐야 한다.
dev 빌드(`--flavor dev`)로 확인한다 — 디버그 시트가 필요하다.

## 원래 PC에서 먼저 확인 (빌드 환경)

알림 작업은 원래 개발 PC가 아닌 Windows PC에서 했다. **iOS는 한 번도 빌드하지 못했고**, Android 빌드 조건도 그 PC 기준으로 맞췄다.

| # | 확인 | 방법 | 기대 | 결과 |
|---|---|---|---|---|
| 0-1 | Flutter 버전 | `flutter --version` | 작업한 PC는 3.47.9. 다르면 아래 빌드가 더 중요하다 | |
| 0-2 | Android 빌드 | `flutter pub get` → `flutter build apk --flavor dev --debug` | 성공 | |
| 0-3 | iOS 빌드 | `flutter build ios --flavor dev` | 성공 (`AppDelegate.swift`에 알림 delegate 한 줄 + 새 패키지) | |
| 0-4 | 알림 패키지 버전 | `pubspec.yaml`의 `flutter_local_notifications: ^22.3.3` | 그대로 둬도 된다. 아래 참고 | |

**알림 패키지를 22.3.x로 묶은 이유.** 23.x는 Android에서 AGP 9.1.1 이상 · compileSdk 37 이상을 요구한다.
작업 당시 AGP는 9.1.0(`android/settings.gradle.kts`, 레포에 있어 어느 PC든 같다), compileSdk는 36(설치된 Flutter의 기본값 — **PC의 Flutter 버전에 따라 다르다**)이었다.
원래 PC의 Flutter가 compileSdk 37을 기본으로 쓰고 AGP를 올려도 되는 상태면 23.x로 올릴 수 있다 — 꼭 올릴 필요는 없다(22.3.3으로 필요한 기능은 다 된다).
올린다면 고칠 곳은 `android/settings.gradle.kts`의 AGP 버전과 `pubspec.yaml` 한 줄이고, Dart 쪽은 `lib/data/notification/local_notification_scheduler.dart`만 보면 된다.

## 준비

- 오늘 화면의 **날짜 제목을 길게 누르면** 디버그 시트가 열린다. 가운데에 알림 시험 버튼 둘:
  - **알림 지금 보내기** — 누르는 순간 띄운다.
  - **1분 뒤 알림 예약** — 예약만 한다. 누른 뒤 앱을 내리거나 · 끄거나 · 화면을 잠그고 기다린다.
  - 둘 다 앱의 알림 설정(켜짐/꺼짐)과 무관하게 OS에 바로 건다. 권한이 없으면 OS 창이 먼저 뜬다.
- 실제 흐름(출근 → 퇴근 시각에 알림)을 빨리 보려면 **출근 변경**으로 출근 시각을 앞당긴다.
  예: 지금 15:00이면 출근을 06:58로 → 일반 근무 기준 15:58에 울린다(점심 1시간 포함 9시간 뒤).
  반차를 체크하면 4시간 뒤라 더 쉽다(출근 10:58 → 14:58).
- 디버그 시계를 옮겨도 알림은 **실제 시각**에 맞춰 울린다(앱 시각 − 옮긴 만큼).

결과는 ✅ / ❌ 와 메모(기종 · OS 버전 · 늦은 시간)로 적는다.

## 1. 공통 — 실제 흐름

| # | 확인 | 방법 | 기대 | 결과 |
|---|---|---|---|---|
| 1-1 | 첫 평일 출근 때 묻는다 | 앱을 새로 깔고(또는 데이터 삭제) 평일에 출근하기 | 출근이 찍히고 그 위에 "퇴근할 때 알려드릴까요?" + 알림 미리보기 | |

| 1-5 | 퇴근하면 예약이 사라진다 | 퇴근 시각 2분 전으로 맞춘 뒤 바로 퇴근하기 | 그 시각에 아무것도 오지 않는다 | |
| 1-6 | 출근 변경 → 새 시각 | 예약된 상태에서 출근 시각을 5분 늦춘다 | 원래 시각엔 안 오고 5분 뒤에 온다 | |

| 1-11 | 밤을 넘긴 뒤 | 퇴근을 안 찍고 앱을 내려둔 채 다음 날 연다 | 엉뚱한 알림이 뜨지 않는다. 오늘 화면은 출근 전 | |
| 1-8 | 마지막 근무일 문구 | 금요일(또는 디버그 시계를 금요일로) + '두 달치 기록' 시드 → 퇴근 시각 맞추기 | 제목 "이번 주 근무 시간을 다 채웠어요!", 본문 "…즐거운 휴일 보내세요!" | |
| 1-9 | 거절 → 토스트 | 새로 깔고 "안 받을래요" | "알림은 설정에서 언제든 켤 수 있어요". 다음 출근 때 다시 묻지 않는다 | |
| 1-10 | 주말 출근은 안 묻는다 | 새로 깔고 디버그 시계를 토요일로 → 출근 | 다이얼로그 없음. 평일로 돌려 출근하면 그때 묻는다 | |

## 2. 앱 상태별 — "1분 뒤 알림 예약"으로

| # | 상태 | 방법 | 기대 | iOS | Android |
|---|---|---|---|---|---|

| 2-2 | 백그라운드 | 예약하고 홈으로 나간다 | 배너 + 소리/진동 | | |

## 알려진 한계 (버그 아님)

- **예약 시각에 폰이 꺼져 있었으면** 켠 뒤에 늦게 뜰 수 있다.
- **Android에서 설정 > 앱 > 강제 종료**를 하면 OS가 예약을 지운다. 앱을 다시 열면 다시 걸린다.
- **알림 시각이 자정을 넘기면 보내지 않는다.** 16:30에 출근한 일반 근무일은 8시간 뒤가 다음 날 00:30이라 알림이 없다.
- **한 번 울린 날은 다시 "바로 띄우기"를 하지 않는다.** 울린 뒤 퇴근 취소·알림 껐다 켜기를 해도 조용하다. 퇴근 시각이 뒤로 밀리면(반차 해제 등) 새 시각에는 온다.
- **Android는 몇 분 늦을 수 있다.** 정확한 알람 권한(사용자가 따로 허용 + Play 심사)을 쓰지 않기로 했다.
